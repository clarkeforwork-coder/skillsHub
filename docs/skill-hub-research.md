# 私人 Skill Hub 參考研究

查閱日期：2026-10-29。範圍為官方產品頁與專案 README；尚未下載、安裝或操作這些桌面應用，因此下列功能是官方描述，並非實測結論。此次僅研究，未修改 SkillsHub 程式。

## 已確認的產品做法

### xingkongliang / Skills Manager

產品以中央收藏庫為核心，將收藏與部署分開。官方頁顯示每個 Skill 的工具圖示可直接切換啟用／移除，也有來源更新提示。收錄來源包括 Git、資料夾、壓縮檔與 skills.sh。可用 Preset 將一組 Skill 套用至工具，並以符號連結或複製部署；另提供私人 GitHub 備份與跨機同步。[官方產品頁](https://skillsmanager.dev/)

README 更明確區分全域、各工具與專案工作區；工作區會列出從其他途徑安裝的 Skill。收藏選取器將搜尋、多選及目標工具放在同一面板。支援標籤／來源篩選、完整文件預覽、上游內容比較和活動紀錄。Preset 套用是一次性的配置，不是持續同步。專案可與中央庫雙向同步。[官方 README](https://github.com/xingkongliang/skills-manager#features)

### jiweiyeah / Skills Manager

這是另一個同名產品。重點是自動偵測工具、接管既有 Skills、中央保存單一副本，再逐工具開關連結。官方流程區分「先唯讀偵測」與「啟用後才寫入」。市場內可以查看來源並安裝；另提供中文／英文翻譯、本機靜態掃描與選用的 LLM 審查。[官方產品頁](https://skillsmanager.freeourdays.com/)

README 列出命令面板，以及與桌面程式共用資料的 CLI。`adopt --dry-run` 可預覽接管既有收藏，`list` 顯示逐工具連結狀態，`doctor`／`fix` 用於偵測和修復同步問題。翻譯使用 LLM，不能據此稱為純離線功能。[官方 README](https://github.com/jiweiyeah/Skills-Manager#-key-features)

## 公開目錄與收藏平台的補充對照

| 產品 | 官方頁面可確認的流程 | 適合借鏡之處 |
| --- | --- | --- |
| skills.sh | 排行／趨勢、主題、官方來源與審查入口；Packs 可混合公開 Skill、檔案與 GitHub 來源，以一條指令安裝。[Packs 文件](https://www.skills.sh/docs/packs) | 把一組方法整理成可重複使用的任務套組；Packs 是不公開列出的連結，**不是存取控制**，持有網址者可查看與安裝 |
| SkillsMP | 入口接受任務、名稱、儲存庫與帳號；結果可依語言、職業、領域、類別、更新時間篩選。[搜尋頁](https://skillsmp.com/search) | 搜尋結果具備多維度縮小範圍的能力，且保留來源；其目前 API 文件明確描述關鍵字搜尋，不能據此宣稱已驗證 AI 語意推薦。[API 文件](https://skillsmp.com/docs/api) |
| Agent Skill Hub | 官方文件描述：GitHub 匯入先掃描，再挑選 Skill 路徑；詳情含摘要、檔案樹、版本、分支、路徑、commit 與安裝片段，並提供 skillsets。[Web platform 文件](https://doc.agentskillhub.dev/guide/web-platform) | 將「挑選收錄哪些項目」放在批次匯入前，讓 Skill 的完整內容與版本可檢查 |

## 對本專案的啟示（設計推論）

| 使用問題 | 可借鏡的設計 | 目前這版的缺口 |
| --- | --- | --- |
| 收藏越來越多，不知道怎麼挑 | 場景集合／Preset，搭配標籤與來源篩選 | 主要依靠卡片與字面搜尋；缺少任務入口與常用組合 |
| 不知道某個工具到底有哪些 Skill | 工具／專案工作區，顯示實際狀態 | 有安裝標籤，但缺乏工具視角與完整專案概況 |
| 收錄後還要繼續維護 | 來源、版本、更新差異與活動紀錄 | 有來源與摘要比對；沒有更新流程與差異畫面 |
| 批次配置太繁瑣 | 同一選取面板內搜尋、多選、選工具、套用組合 | 安裝是末端動作，收藏與目標環境的關係不夠直覺 |
| 英文描述難判讀 | 本地可編輯的中文用途摘要，原文仍可查閱 | 直接顯示原始英文描述，需要使用者自行解讀 |

這些私人管理器的共同設計重點是「收藏庫 → 選取／組合 → 工具與專案配置 → 持續維護」。我們可以先釐清這條流程，再評估任務推薦應放在哪裡。上述來源沒有充分證據證明它們已提供「純本機理解任意中文任務，並產生推薦理由」；不應把 Preset、關鍵字搜尋或 LLM 翻譯混稱為這種能力。

建議產品主軸仍放在私人收藏庫：採用較密集的結果列表與旁側預覽，先收錄再安裝，以任務套組減少反覆勾選。未來若加入推薦，理由應指向具體描述、標籤或使用筆記，區分「匹配依據」與未經驗證的適用性判斷。

## 研究限制

- 未以星數或官網數量判定產品品質，也未做全面市場排名。
- 官網顯示的工具路徑可能與工具最新文件不同；例如兩個管理器頁面列出 Codex 的 `.codex/skills`。這是觀察到的產品描述，不應直接取代 Codex 官方相容性規則。
- 共用中央庫的符號連結能避免副本分歧，但是否採用仍需依使用者是否希望保留獨立版本決定；不能只因別人採用就遷移既有收藏。
